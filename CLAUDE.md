# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**ReqTrace** — a requirements-to-code traceability chatbot for automotive embedded software (Sprint 2 course project; brief in `125.md`). It answers questions about AUTOSAR SWS requirements with source-linked citations and a split-window PDF/code preview, checks a permitted C repository for implementation evidence, and generates SRS → SWS → code traceability reports.

**Progress: WP1–WP7 are done. The project is complete.** The corpus is ingested (7 SWS documents, 1860 requirements, 1253 code units — CanNm, Com and PduR joined on 2026-08-27, closing finding A5's gap); spec §4's five retrieval stages are assembled behind `retrieval/pipeline.py`; the agent, chat SSE endpoint, read endpoints, threads and setup API are live; and all **five** tools are registered. WP4 added the three-tier evidence engine (`engines/evidence.py`), traceability reports as background jobs (`engines/report.py` + `api/reports.py`), and the judge evaluation (`evaluation/judge_eval.py`). Measured facts worth not re-deriving live in `docs/findings/2026-08-26-corpus-and-toolchain-findings.md`; C9–C12 and D3–D4 are WP3's, A7/C13/D5/D6 are WP4's.

**Frontend rules learned the hard way in WP5.** (1) This Next/React is newer than model training data (`frontend/AGENTS.md`, finding C7): React's `set-state-in-effect` and `refs` rules reject setting state in an effect body or writing a ref during render — derive or key instead. (2) A width override on a `Sheet` must carry the same `data-[side=right]:` qualifier the base class uses, or it silently loses on specificity. (3) The transcript must never depend on persistence succeeding — see `AppShell`'s `unsaved`. (4) **The React Compiler is on** (`reactCompiler` in `next.config.ts`): write plain components, no `useMemo`/`useCallback`. The exceptions keep theirs, each with a comment saying why — memos whose semantics the compiler cannot carry (`AppShell`'s `source`, an impure create-once, and `layout`, a localStorage snapshot) and the three hooks the compiler bails out on because of their `for await` streaming loops (`use-chat-stream`, `use-report`, `use-ingest-log`).

**WP7 changed the retrieval pipeline twice, both driven by measurement — do not revert either without re-running `evaluation/ragas_eval.py`.** (1) An *inferred* filter that matches nothing is dropped and the search retried unfiltered (`retrieval/pipeline.py`, logged as `dropped_filter`); a **caller-supplied** filter is never dropped, because "no CanSM requirement matches" is a true answer to a question that named CanSM. (2) An inferred *module* filter applies only when the question actually names that module (`self_query.question_names_module`) — `Can` is matched **case-sensitively**, since this corpus writes the module `Can`, the bus `CAN` and the verb `can`. Both fixes came from the RAGAS run: the pipeline was returning zero results for a requirement that exists, and filtering "CAN controller state" to CanSM.

**The headline WP7 result is uncomfortable and stays in the README.** The golden set is now 35 questions in two kinds, reported separately since 2026-08-28 (`kind` field; per-kind tables in `ragas_eval.py`). On the 25 lookup questions the **naive top-k baseline beats the full pipeline** (hit rate 1.000 vs 0.920–0.960 across runs — expansion/rerank are nondeterministic LLM stages); each question was written *from* one requirement, so BM25 alone nails it. The 10 enumeration questions did not rescue the pipeline: it wins RAGAS context recall (+0.190) but *redistributes* ground-truth id recall rather than adding it (0.577 vs 0.607) — it recovers diffuse-vocabulary questions and loses exact-vocabulary ones. Do not "fix" any of this by rewriting the golden set to flatter the pipeline; the 25 lookup questions are frozen, and new questions get a `kind` and their own table.

**Three evaluations spend money and one does not.** `make test` (1116 tests) is offline and free. `evaluation/judge_eval.py`, `evaluation/ragas_eval.py` and `evaluation/injection_eval.py` all call real models; `ragas_eval table` and `injection_eval table` reprint the saved run for free. `make smoke` boots both servers and uses the app for real (~$0.006) — it reuses servers it finds already running and stops only what it started.

**WP6's measured result, which matters more than its green suite.** `evaluation/injection_eval.py` ran the 10 fixtures against the real models: **8 held, 2 compromised** (the 2026-08-28 re-run scored 9/1 — prompt-extraction happened to paraphrase instead of enumerating; treat that as a flaky hold, not a fix). Both failures are real and documented rather than papered over — (a) *prompt extraction*: the agent used to hand over its entire system prompt on the first ask, which is why `agent/prompts.py::NON_DISCLOSURE_RULE` exists; the verbatim dump now stops but the **tool list leaks on most phrasings tried**, because tool schemas arrive in the API's `tools` array rather than in the prompt — do not keep rewording it. (b) *fence-escape-requirement*: an instruction inside poisoned requirement text moved a judge verdict `partial → missing` **even though the fence held**. That is the honest limit of fencing: it bounds the blast radius to one wrong verdict (the judge returns a status plus candidate *positions*, so it still cannot fabricate a file or a line), it does not stop steering.

**Three WP6 rules.** (1) `retrieval/prompting.py::fence` is now the **only** fence in the codebase — `agent/tools.py` had a second one, and two implementations meant two places to harden. Never wrap untrusted text by hand; the helper also strips the delimiter out of the payload (`neutralise`), which is what stops a poisoned chunk from closing its own fence. (2) `api/chat.py::LIMITER` is **module-level state**, so any test that posts to `/chat` more than a few times must `LIMITER.reset()` first — `tests/test_chat_api.py`'s `wired` fixture does. (3) The adversarial suite (`tests/test_injection.py` over `tests/injection_set/*.json`) asserts only properties that survive a *fully compromised* model, because every model reply in tests is scripted — "the model refused" would be a fact the test invented. Adding a fixture with a new `kind` fails the suite until it has a check.

**Two WP4 rules that are easy to break by accident.** (1) `engines.evidence`'s `blind` flag is a *measurement* mode for the judge evaluation only — it withholds the `@req`/`!req` evidence, which would make every shipped verdict worse; never set it in the product path. (2) The report cost ceiling is configured in two places and `engines.report.ceiling_usd` decides: the `MAX_REPORT_COST_USD` environment variable wins when set, the manifest's `limits.max_report_cost_usd` applies otherwise.

**The frontend runs live by default as of WP5.** `frontend/lib/events.ts` is the *authority* on the chat wire format (`api/chat_events.py` is the Python side; do not fork them) and `frontend/lib/reports.ts` is the same thing for reports (`api/reports.py`). `chatSourceKind()` selects the world and **`lib/threads.ts` follows it** — threads and chat must never be in different worlds. `NEXT_PUBLIC_REQTRACE_CHAT_SOURCE=canned` still replays the committed fixture with no backend, no index and no key; that path is deliberately kept working, so anything that fetches must be gated on `chatSourceKind() === "live"` or the demo fills with error panels.

## Locked decisions (do not re-litigate without the user)

- **Stack:** Next.js (App Router, TS, Tailwind + shadcn/ui) frontend at `frontend/`; Python 3.12 + FastAPI + LangChain v1 backend at `backend/`; managed with `uv`. Frontend reaches backend ONLY via the Next.js `rewrites()` proxy (`/api/py/:path*` → `localhost:8000`) — no CORS config.
- **All LLM, embedding, and rerank calls go through OpenRouter** (OpenAI-compatible, `base_url=https://openrouter.ai/api/v1`). No local models, no torch. Model IDs are pinned in `projects/autosar-can/project.yaml`, never hard-coded.
- **Corpus:** seven AUTOSAR SWS PDFs (CAN Driver, CAN Interface, CAN Transport Layer, CAN State Manager, CAN Network Management, Com, PDU Router; R23-11, fetched from autosar.org at ingestion) traced against `openAUTOSAR/classic-platform` (C, pinned SHA). Fetched artifacts live in `data/` which is **gitignored — never commit PDFs or the cloned repo**.
- **Corpus abstraction ceiling:** downstream code depends only on the `Requirement`/`CodeUnit` Pydantic models + the `project.yaml` manifest. Format handling is a plain dict of loader functions — do NOT introduce plugin registries or adapter class hierarchies.
- **Architecture:** tool-calling agent for conversation; deterministic engines behind the 5 tools (`lookup_requirement`, `search_requirements`, `search_code`, `check_implementation`, `generate_traceability_report`). The RAG pipeline stages (multi-query → self-query filters → BM25+dense with RRF → LLM rerank) are pure functions. Requirement IDs are resolved by exact SQLite lookup, never semantic search.
- **Storage:** SQLite (registry, threads with full SSE event streams per message, verdict cache keyed `(req_id, git_sha, model_id)`, embedding cache by content hash) + Chroma (vectors, collection per project) + in-memory BM25 built at startup.
- **Chat protocol:** SSE with a `{type, data}` envelope (`token|tool_start|tool_result|citation|usage|done|error`). Citations are structured events, never parsed out of prose. Threads replay stored events on reload — UI state (tool chips, citations, cost lines, checkpoint restore) must come from those events.
- **Security posture:** retrieved documents AND code are untrusted input — always fenced as data-not-instructions in prompts. Only the chat agent has tools; the evidence judge and reranker must remain tool-less. File serving resolves against the indexed snapshot only. Cost hard stop via `MAX_REPORT_COST_USD`.
- Reports are batch jobs (FastAPI BackgroundTask + in-process registry) — no Celery/Redis. Judge verdicts allow `unverifiable`; never force a binary.

## Commands

- `make dev` — boot backend (uvicorn :8000) + frontend (next dev) together
- `make install` — uv sync + npm install; also installs the git pre-commit hook (`make install-hooks` → `.githooks/pre-commit`, which runs deps-check + ruff)
- `make test` / `make lint` — the offline suite (1116 tests) / deps-check + ruff + eslint. CI (`.github/workflows/ci.yml`) runs the same targets plus the frontend typecheck and production build.
- `make deps` / `make deps-check` — regenerate `dependencies.txt` from `backend/uv.lock` + `frontend/package-lock.json` / fail if it drifted (platform-independent: it reads the lockfiles, never the venv)
- `cd backend && uv run pytest` — backend tests; single test: `uv run pytest tests/test_x.py::test_name`
- `cd backend && uv run python -m ingestion.run ../projects/autosar-can/project.yaml` — the **only** ingestion entry point: fetch + parse + index + embed the corpus (idempotent — a second run downloads nothing and embeds nothing; writes `data/extraction_report.md` and `data/spot_check.md`). Useful flags: `--skip-embeddings` (no API key needed), `--force`, `--stop-after {docs,extract,code,store,embed}`, `--quiet`; also `--db`, `--chroma`, `--batch-size` for non-default targets.
- `cd frontend && npm run dev` / `npm run build`
- `make smoke` — the end-to-end test (F7.1): boots whatever is not already running, asks three real questions **through the frontend proxy**, runs a scoped report to completion, deletes its own threads, and stops only the servers it started. **Spends money** (~$0.006). Exits 0/1. `--keep` leaves the servers it booted running.
- `cd backend && uv run python -m evaluation.ragas_eval run|table` — the RAGAS comparison (F7.2), naive top-k vs the full pipeline over `tests/fixtures/ragas_golden_set.json`. **Spends money** (~$0.30); `table` reprints the saved run for free.
- `cd backend && uv run python -m evaluation.injection_eval run|table` — the **live** adversarial measurement (F6.2). `run` puts every `tests/injection_set/*.json` fixture through the real product path against the pinned models and reports held/compromised (**spends money**, ~$0.01); `table` reprints the last run's README table for free from `docs/evaluations/injection-eval.json`. The pytest suite proves the defences are *wired*; this is the only thing that says whether they *work*.
- `cd backend && uv run python -m evaluation.judge_eval build|run` — the judge evaluation (F4.4). `build` derives the labelled set from the corpus' `@req`/`!req` annotations and writes `tests/fixtures/judge_eval_set.json` (free); `run --limit-per-class N` judges a sample and prints the README table (**spends money** — it calls the judge model; a re-run is free because verdicts are cached). `--mode {sighted,blind,both}` selects the measurement arm (default `both`).
- Requires `OPENROUTER_API_KEY` in `backend/.env` (see `.env.example`)

## Working conventions

- Conventional commits on `main`; this is the graded submission repo.
- Golden fixtures under `backend/tests/fixtures/golden/` are the contract for ingestion — extraction changes must keep them green (recall ≥90%) or update them deliberately with hand-verified labels.
- Engine tests use recorded/mocked LLM replies; tests must not hit OpenRouter.

## Rules

- Never add "Co-Authored-By" lines to commits or include Claude attribution in commit messages and PR descriptions.
- Do NOT Commit any secrets — no API keys, passwords, or tokens in the files.
- Never Push without my approval first.
- After any dependency change, regenerate `dependencies.txt` with `make deps` (or `python3 scripts/gen_dependencies.py`) — never edit it by hand. `make lint` runs `make deps-check`, which fails on drift, so a stale file will be caught; adding a dependency and not regenerating went unnoticed for two work packages before that guard existed.
- Don't add any external libraries or packages without asking me first.
- Never delete anything without asking for permission while providing a sentance summary of why you are deleting it.
- If anything is unclear, ask me a question before making assumptions.
